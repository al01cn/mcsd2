# Java sound-event compatibility

The Java exporter expands audited historical event names regardless of the
selected game version. This is name compatibility, not a promise that one pack
format works in every client or that an event introduced later exists in an old
game. Bedrock output and custom namespaces are not expanded.

## Data and sources

`lib/java-sound-history.ts` stores directed naming transitions, with the version
in which the new name was introduced. Its explicit family suffix lists are
data compression, not prefix-based guessing at runtime.

The audit compares original Mojang `sounds.json` event keys and their sound
references before/after a transition, then cross-checks named-event mappings.
Renamed sound files, reused samples, and identical audio alone are not sufficient
evidence for merging events. Existing actions split into separate event names
are represented by multiple directed edges.

Primary asset discovery:

- `https://piston-meta.mojang.com/mc/game/version_manifest_v2.json`
- The `assetIndex.url` in each selected version manifest.
- The `minecraft/sounds.json` object in that asset index.
- `https://resources.download.minecraft.net/<first-two-hash-characters>/<sha1>`

The verification script pins the SHA-1 hashes of the downloaded original sound
definitions for the 1.8.9/1.9, 1.12.2/1.13, 1.14/1.16, 1.16/1.17,
1.20.6/1.21 and 1.21.5/1.21.6 comparisons. Hashes are checked before parsing.
Earlier pre-1.9 names retained in 1.8.9 are included.

Cross-check references:

- ViaVersion `SoundEffectMappings1_9.java` and `NamedSoundMappings1_13.java`,
  under `common/src/main/java/com/viaversion/viaversion/protocols/`.
- ViaVersion/Mappings, pinned revision
  `588376a2839cabfad448166dfb8f3ecd0eb9f637`, under `mappings/diff/`.
- The same revision's `mapping-1.19.4.json` and `mapping-1.20.3.json`
  extracted sound registries verify the old brush and wind-charge names.
  Their Mojang asset indexes were subsequently updated and now contain newer
  names, so those indexes cannot establish the older registrations.

Do not import a protocol translator's entire fallback map. For example:

- `entity.item_frame.add_item -> random.pop` is not a pickup-event rename.
- `entity.shulker.ambient -> ambient.cave.cave` is a fallback, not a rename.
- `entity.wolf.howl -> entity.wolf_angry.ambient` is not a rename.
- Preserve `item.fireCharge.use` and `fireworks.largeBlast` case.
- The guardian and generic/player/hostile families retain their own meaning;
  a same-sample mapping to a different creature or category is not sufficient.

Removed events without a verified successor retain their last known name.
No hypothetical old names are generated for newer events.

## Expansion and conflict rules

For a selected current event, emit that event and its historical ancestors.
For a selected old event, emit its explicitly mapped successors and their
historical names. Never continue forward from a shared ancestor encountered
during this reverse traversal. Thus `block.stone.break` adds `dig.stone`, not
`block.stone.place`; directly selecting `dig.stone` covers both actions.

Merge audio at each output event, deduplicating the final sound path. Direct
bindings have priority for weights. Otherwise, use the history table's stable
current-to-old ordering; ties across audio IDs keep the first audio. Subtitles
keep the first nonempty subtitle in audio order. Default weight 1 is omitted.
Known `minecraft:`-qualified names are emitted as unqualified keys inside
`assets/minecraft/sounds.json`. Other namespaces and unknown names are untouched.

The editor manifest retains user bindings, weights, and folders. Only its
`soundsJson` snapshot is expanded. Imports retain existing historical bindings.
Without editor metadata, a shared old name cannot reveal whether it was chosen
explicitly or generated by a previous exporter; it is treated as an explicit
binding. Keeping `.editor/mcsd.json` preserves the original intent on round-trip.

## Maintenance and verification

Run the offline regression suite with `bun test`. To recheck source keys and
the coverage of the pre-1.9 catalog, run:

```sh
bun scripts/verify-java-sound-history.ts
```

This optional check needs network access. Normal editing, searching, exporting,
and unit tests never fetch mapping data. The source check verifies existence
and coverage; semantic review is still required before adding new transitions.

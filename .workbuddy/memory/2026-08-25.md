# 2026-08-25

## 修复：手机端卡在加载画面

**问题**：手机（局域网 IP 访问）测试时，页面一直卡在「正在准备移动版工作区」加载遮罩，进不去工作区。

**根因**：`MobileLoadingOverlay` 用 `snapshot.loaded && snapshot.status === "success"` 作为露出条件，导致移动端工作区被 FFmpeg WebAssembly（约 30MB `ffmpeg-core.wasm`）的下载+编译过程硬性阻塞。而移动端界面（项目列表、音频管理）本身不依赖 FFmpeg，只有音频探测/转换才需要（`probeAudio`/`toOGG` 内部都 `await this.load()` 兜底）。

**修复**：
- `app/ui/mobile-loading-overlay.tsx`：露出条件改为有上限的 hydration 窗口（650ms 定时器），不再等待 FFmpeg；FFmpeg 转为后台加载，进度/错误改为底部非阻塞横幅 `.mobile-ffmpeg-banner`（含重试按钮）。
- `app/globals.css`：`mobile-loading-overlay-dismiss` 动画从 3.18s 改为 300ms 快速淡出；新增 `.mobile-ffmpeg-banner` 样式。

**备注**：FFmpeg 在移动端加载缓慢/失败的具体原因（CDN 测速、wasm 编译内存、移动浏览器 worker/blob 兼容性）未在本轮定位，后续如需移动端转换功能稳定，可单独排查。类型检查与 lint 均通过。

## 更正：还原遮罩 + 根因修复（用户要求）

用户反馈解耦方案不对——遮罩必须**始终挡住用户**直到 FFmpeg 成功加载，防止未就绪时乱点。已还原：

- `app/ui/mobile-loading-overlay.tsx`：还原为阻塞式（`loaded && status === "success"` 才放行，含进度条、错误态 + 重试按钮）。
- `app/globals.css`：还原 `mobile-loading-overlay-dismiss` 为 3.18s；移除 `.mobile-ffmpeg-banner`。

同时修复"卡死"真正根因：`lib/ffmpeg.ts` 中 `candidate.load()`（worker 导入 + wasm 编译）在部分移动浏览器可能长时间无响应，新增 `FFMPEG_LOAD_INIT_TIMEOUT_MS = 60000` 的 AbortController 超时，保证加载要么成功、要么切源、要么进入错误态弹出重试，绝不无限转圈。

**关键约定**：移动端加载遮罩是**刻意设计**的硬阻塞，勿再改为后台加载/非阻塞方案。类型检查与 lint 均通过。

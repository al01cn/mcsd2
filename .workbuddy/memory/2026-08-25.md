# 2026-08-25

## 修复：手机端卡在加载画面

**问题**：手机（局域网 IP 访问）测试时，页面一直卡在「正在准备移动版工作区」加载遮罩，进不去工作区。

**根因**：`MobileLoadingOverlay` 用 `snapshot.loaded && snapshot.status === "success"` 作为露出条件，导致移动端工作区被 FFmpeg WebAssembly（约 30MB `ffmpeg-core.wasm`）的下载+编译过程硬性阻塞。而移动端界面（项目列表、音频管理）本身不依赖 FFmpeg，只有音频探测/转换才需要（`probeAudio`/`toOGG` 内部都 `await this.load()` 兜底）。

**修复**：
- `app/ui/mobile-loading-overlay.tsx`：露出条件改为有上限的 hydration 窗口（650ms 定时器），不再等待 FFmpeg；FFmpeg 转为后台加载，进度/错误改为底部非阻塞横幅 `.mobile-ffmpeg-banner`（含重试按钮）。
- `app/globals.css`：`mobile-loading-overlay-dismiss` 动画从 3.18s 改为 300ms 快速淡出；新增 `.mobile-ffmpeg-banner` 样式。

**备注**：FFmpeg 在移动端加载缓慢/失败的具体原因（CDN 测速、wasm 编译内存、移动浏览器 worker/blob 兼容性）未在本轮定位，后续如需移动端转换功能稳定，可单独排查。类型检查与 lint 均通过。

## 更正：还原遮罩 + 根因修复（用户要求）

用户反馈解耦方案不对——遮罩必须**始终挡住用户**直到 FFmpeg 成功加载，防止未就绪时乱点。已还原：

- `app/ui/mobile-loading-overlay.tsx`：还原为阻塞式（`loaded && status === "success"` 才放行，含进度条、错误态 + 重试按钮）。
- `app/globals.css`：还原 `mobile-loading-overlay-dismiss` 为 3.18s；移除 `.mobile-ffmpeg-banner`。

同时修复"卡死"真正根因：`lib/ffmpeg.ts` 中 `candidate.load()`（worker 导入 + wasm 编译）在部分移动浏览器可能长时间无响应，新增 `FFMPEG_LOAD_INIT_TIMEOUT_MS = 60000` 的 AbortController 超时，保证加载要么成功、要么切源、要么进入错误态弹出重试，绝不无限转圈。

**关键约定**：移动端加载遮罩是**刻意设计**的硬阻塞，勿再改为后台加载/非阻塞方案。类型检查与 lint 均通过。

## 修复：手机端音频列表无滚动容器

**问题**：音频步骤（`activeStep === 0`）的 `mobile-audio-list` 直接平铺所有音频，文件多时把「转换/下一步」按钮顶出屏幕，用户需滑到底才能点击。

**修复**：`app/globals.css` 为 `.mobile-audio-list` 增加独立滚动容器样式——`max-height: 46vh`（带 `46dvh` 回退）、`overflow-y: auto`、`overscroll-behavior: contain`、主题化细滚动条（`scrollbar-color: var(--mcsd-grass) var(--mcsd-surface-strong)`）、iOS `-webkit-overflow-scrolling: touch`。列表在自身容器内滚动，按钮保持在可见范围。

## 新增：手机端音频长按操作窗口（修改 key / 移除）

**需求**：音频项长按弹出底部操作窗口，含「修改 key」「移除」两项。

**实现**：
- `app/ui/mobile-workspace.tsx`：给 `.mobile-audio-item` 加长按手势（`onPointerDown` 非 mouse 时 450ms 定时器 → `onPointerUp/Cancel` 取消；`isPreparingAudio` 时禁用）。长按弹出 `.novice-context-menu.is-touch`（复用现有 action sheet 样式）+ backdrop；「修改 key」打开 `.novice-event-manager__overlay` + `.novice-event-manager__rename-dialog` 输入弹窗（空/重复校验）；「移除」直接 `onRemoveAudio`。新增 `onRenameAudioKey` prop 与 i18n 文案（modifyKey/removeAction/keyLabel/keyPlaceholder/keyEmptyError/keyDuplicateError/cancel/save）。
- `app/ui/desktop-workspace.tsx`：新增 `renameAudioKey(audioId, rawKey)`——规范化（小写、`[^a-z0-9_]`、截断 `MAX_AUDIO_KEY_LENGTH=8`）、查重（返回 `"empty"`/`"duplicate"`/`null`），更新 `audioFiles` 的 key；**关键联动**：仅当 `customEventSuffixes[audioId] === 旧 key`（事件后缀尚未自定义，初始值即 key）时，同步更新 `customEventSuffixes`/`customEventNames`/`audioEventBindings`/`audioEventWeights` 中的 `mcsd.<旧key>` → `mcsd.<新key>`。
- `app/globals.css`：`.mobile-audio-item` 加 `-webkit-touch-callout`/`user-select: none` 防长按系统选中；新增 `.mobile-action-sheet__header`（菜单标题行）与 `.mobile-key-editor__error`（错误提示）。

**约定**：`customEventSuffixes[audioId]` 初始值即 `audio.key`（见 `handleFiles`），作为「事件后缀是否已自定义」的判据；改 key 是否联动事件名，以此对比为准。类型检查与 lint 均通过。

## 改动：手机端上一步/下一步改为右上角图标按钮

**需求**：把底部「上一步/下一步」导航改为步骤条右上角的图标按钮，免去滑到底部。

**实现**（`app/ui/mobile-workspace.tsx` + `app/globals.css`）：
- 步骤条 `<ol class="mobile-step-bar">` 包进新的 `.mobile-step-header`（flex，步骤条 `flex:1`），右侧加 `.mobile-step-nav`，含两个 `isIconOnly` 图标按钮：
  - 上一步（ArrowLeft）：`activeStep===0 || isPreparingAudio` 禁用，点击 `onStepChange(activeStep-1)`。
  - 下一步（ArrowRight，绿色主按钮）：`activeStep===2` 或（step0 且无音频/转换中）禁用；step0 点击 `onPrepareAudio`（转换后 goToStep(1)），step1 点击 `onStepChange(2)`；step0 转换中显示 spinner。
- 新增 `.mobile-convert-progress` 精简进度条（`activeStep===0 && isPreparingAudio` 时显示「正在处理 X/Y · Z%」），取代原底部按钮的进度反馈。
- 移除底部导航：step0 的「转换并设置事件」按钮、step1 的 `mobile-screen-actions`（上一步+检查并导出）、step2 的「上一步」；step2 保留「返回音频」（`mobile-primary-action`）。
- 新增 i18n：`next`（下一步/Next）。

**备注**：`.mobile-secondary-action` 与 `.mobile-screen-actions` 的 CSS 已无组件引用（死代码，暂保留未清理）。类型检查与 lint 均通过。
